Core CaaS Architecture: The 5 Strategic Solutions

NIST Standardized Core

Post-Quantum Cryptography

Protect sensitive data, credentials, and API communication channels against Harvest-Now-Decrypt-Later (HNDL) adversaries. Implements the NIST FIPS 203 (ML-KEM) key encapsulation and FIPS 204 (ML-DSA) signature algorithms via @noble/post-quantum (not a validated module), plus hybrid X25519 + ML-KEM key encapsulation for coexistence with classical cryptography.

Explore PQC Infrastructure
Self-Hosted Microservice

Cryptography-as-a-Service Daemon

A Fastify REST microservice that exposes crypto-lib operations with rate limiting and OpenTelemetry instrumentation. Run it in your private cloud or on-premises data centre so keys you manage with it stay on infrastructure you control. No throughput figures are published yet.

Explore CaaS Daemon
Key Management

KMS Provider Interface

One TypeScript interface for key management backends, with envelope encryption (DEK/KEK) through generateDataKey(). AWS KMS and a local in-memory provider are implemented; Google Cloud KMS, Azure Key Vault and HashiCorp Vault are stubs, and PKCS#11 is a software simulation with no HSM support.

Explore KMS Interface
Database & Middleware Security

Zero-Trust Field & Column Encryption

Transparent column encryption for Prisma and TypeORM. A Prisma Client extension and a TypeORM @EncryptedColumn() decorator encrypt configured fields with XChaCha20-Poly1305 before they are written, so database dumps hold only ciphertext for those fields, without schema rewrites.

Explore Field Encryption
Runtime Portability

Edge Runtime Support

crypto-edge adapts crypto-lib to Cloudflare Workers, Vercel Edge, Deno, Bun, and browsers, with runtime detection and text/base64 fallbacks. All operations run in JavaScript or the platform Web Crypto API: crypto-wasm is a placeholder with no WebAssembly module, and there is no constant-time guarantee.
