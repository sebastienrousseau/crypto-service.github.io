Quick start

ML-KEM-768 in three calls.

Install @sebastienrousseau/crypto-lib on Node.js 22 or later, then generate a key pair, encapsulate a shared secret and recover it. Keys, ciphertexts and secrets are hex strings.

What ships in {{version}}

Six building blocks, each with its limits stated.

Post-quantum cryptography

ML-KEM (FIPS 203), ML-DSA (FIPS 204) and SLH-DSA (FIPS 205) through @noble/post-quantum, with native Node.js back ends on 24.7 and later. Hybrid X25519 + ML-KEM KEMs share one v2 combiner; hybrid signatures are Composite ML-DSA; HPKE uses X-Wing. Not a validated module.

Post-quantum

Self-hosted REST service

crypto-server exposes crypto-lib over Fastify with API key or JWT auth, rate limiting, an audit log and OpenTelemetry. No throughput figures are published.

The service

KMS provider interface

AWS KMS (including ML-DSA signing keys), Google Cloud KMS, HashiCorp Vault Transit and a local provider are implemented. Azure Key Vault is a stub; PKCS#11 is a software simulation with no HSM.

KMS

Field encryption

A Prisma Client extension and a TypeORM @EncryptedColumn() decorator encrypt chosen fields with XChaCha20-Poly1305 before they are written.

Field encryption

Edge runtimes

crypto-edge adapts crypto-lib to Cloudflare Workers, Vercel Edge, Deno, Bun and browsers. crypto-wasm is a placeholder: it ships no WebAssembly module.

Edge

CBOM, LSP and MCP

CycloneDX 1.6 or SPDX 3.0 CBOMs from source, a language server that flags weak cryptography, and an MCP server over stdio for AI agents.

Tooling

Algorithm reference

Supported algorithms and standards

Implemented in crypto-lib on the @noble/* libraries; none is a validated cryptographic module. No timing figures are published: run node --require ts-node/register/transpile-only benchmarks/crypto-bench.ts in the repository to measure on your own hardware.
